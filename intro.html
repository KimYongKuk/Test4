데이터 분석 프로세스 교안
상권 분석을 통한 창업 성공 예측 실무

1단계: 문제 정의 & 데이터 피처 설계

1) 문제 정의: "어떤 상권에서 장사가 잘 될까?"

창업 전 반드시 확인해야 할 핵심 질문들:

  • 동네에 사람이 많나? → 유동인구
  • 경쟁 업체는 많나? → 상가업소 수
  • 임대료는 저렴한가? → 부동산 가격 / 공실률
  • 우리가 창업한다면 가장 확인하고 싶은 것은?
성공한 가게의 특징: 역세권, 높은 유동인구, 주차 편의, 적정 경쟁, 프랜차이즈, 주변 오피스/아파트 밀집
실패한 가게의 공통점: 높은 임대료, 낮은 유동인구, 과도한 경쟁, 공실률 높음, 접근성 나쁨

★ 공공데이터 기반 피처 설계 (실제 제공 컬럼 확인 필수)

  1. 희망 피처 리스트 작성
  2. 공공데이터 포털 확인: 열린 데이터 광장, 한국부동산원
  3. 제공 컬럼 ↔ 희망 피처 매핑
  4. 데이터 확보 가능성 검증
핵심 공공데이터 예시:
• 유동인구: 서울시 유동인구 데이터 (시간대별, 연령대별)
• 상가업소: 소상공인시장진흥공단 상가업소 정보
• 부동산: 한국부동산원 상권임대료, 공실률
• 지하철역: 서울교통공사 역별 승하차 인원
2단계: 데이터 수집

2) 데이터 수집 전략

  • 수집 방식: API, 크롤링, 공공데이터 RAW 다운로드
  • API 키 발급: 공공데이터 포털 → 서비스 신청 → 키 발급
  • 수집 코드 작성: Python requests, pandas 활용
# 예: 공공데이터 API 호출 (서울시 유동인구) import requests import pandas as pd url = "http://openapi.seoul.go.kr:8088/[KEY]/json/TbVwablePpntn/1/100/" response = requests.get(url) data = response.json() df = pd.DataFrame(data['TbVwablePpntn']['row'])

수집 후 점검 항목

  • 샘플 데이터 결측치 확인
  • 데이터 양 충분성 판단
  • 트러블슈팅: 인코딩 문제 (cp949 ↔ utf-8), API 제한
3단계: EDA & 데이터 전처리

3) EDA: 탐색적 데이터 분석

  • 단변량: 히스토그램 → 분포 확인
  • 이변량: 산점도, 상관관계 히트맵
  • 범주형: 막대그래프, 파이차트
  • 타겟 중심: 폐업 vs 존속 비교 (박스플롯, 그룹별 평균)

전처리 핵심 기법

항목 방법
결측치 삭제 / 평균·최빈값 대체 / KNN 보간
이상치 IQR, Z-score, 논리적 검증
스케일링 표준화 (StandardScaler) / 정규화 (MinMaxScaler)
병합 공통키 기준 pd.merge()
스케일링이 필요한 경우: 유동인구(수만 명), 면적(m²), 지하철역 거리(m) 등 단위·범위가 다른 수치형 피처
4단계: 머신러닝 모델링

4) 문제 유형 정의

"해당 상권에서 창업 시 폐업할 확률은?" → 이진 분류 문제

모델링 프로세스

  1. 피처/타겟 분리: X (유동인구, 임대료 등), y (폐업여부 0/1)
  2. 범주형 인코딩: LabelEncoder, OneHotEncoder
  3. 훈련/테스트 분리: train_test_split(test_size=0.2)
  4. 모델 선정: 로지스틱 회귀 → 랜덤포레스트 → XGBoost
  5. 불균형 처리: SMOTE, class_weight
  6. 하이퍼파라미터 튜닝: GridSearchCV
  7. 피처 엔지니어링: 유동인구/면적 → 밀도, 경쟁률 등
평가 지표:
• Accuracy (부적합) → F1-score, AUC-ROC 권장
• 폐업 사례가 적은 불균형 데이터셋 특성 반영

전체 프로세스 요약 (Iteration 포함)

  1. 문제정의 → 피처 설계 → 공공데이터 매핑
  2. 데이터 수집 → 결측/충분성 확인
  3. EDA → 이상치/결측치 처리 → 병합 → 시각화
  4. 모델링 → 성능 평가 → 피처 재설계 → 반복
    5. 핵심: 데이터는 있지만, "의미 있는 피처"를 만드는 것이 성공의 열쇠
